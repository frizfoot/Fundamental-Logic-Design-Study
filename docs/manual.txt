[2] 프로젝트 폴더 구조
---------------------------------------------------------------------
  projects/<작업명>/
    project.tcl     설정 (아래 참고)
    note.md         작업 노트 (README 에 자동 반영)
    doc/            스펙 문서
    src/            설계 RTL (.sv .v)        -> Quartus 합성 + Questa
    sim/            테스트벤치 (.sv), wave.do -> Questa 전용
    sdc/            타이밍 제약 (.sdc)        -> Quartus
    quartus/<작업명>.qpf / .qsf  -> GitHub 에 올라감 (디바이스, 핀 배정, 파일 목록)
    quartus/db, output_files/    -> 안 올라감 (빌드 결과, 매번 새로 생김)
    questa_work/                 -> 안 올라감 (Questa 컴파일 결과)

  project.tcl 예시 (SDRAM_256Mb):
    set quartus_family "MAX 10"
    set quartus_device "10M50DAF484C7G"
    set top_module "sdram_ctrl"      <- 합성 최상위 모듈 이름
    set sim_top    "tb_sdram_ctrl"   <- 테스트벤치 모듈 이름 (비우면 sim/ 에 모듈이 1개일 때 자동)


[3] 매일 작업 순서
---------------------------------------------------------------------
  (1) 작업 시작: PULL  (다른 PC 에서 한 작업 받기)
        Quartus : Tools > Tcl Scripts... > scripts/q_git_pull.tcl > Run
        Questa  : Transcript 창에
                  source C:/Users/noelk/Vivado/scripts/q_git_pull.tcl

  (2) 코드 작성: VS Code 등으로 src/ sim/ 에 파일 만들기/수정

  (3) 시뮬레이션 (Questa Transcript 창):
        do C:/Users/noelk/Vivado/scripts/questa_sim.do C:/Users/noelk/Vivado/projects/SDRAM_256Mb
      - 다시 돌릴 때: Transcript 에서 위쪽 화살표(↑) -> Enter
      - 파형 창 배치 저장: File > Save Format... -> projects/<작업명>/sim/wave.do
        (다음부터 자동으로 그 배치로 열림, 다른 PC 에도 같이 감)

  (4) 합성/타이밍 (Quartus):
        File > Open Project > projects/SDRAM_256Mb/quartus/SDRAM_256Mb.qpf
        Processing > Start Compilation
        Tools > Timing Analyzer  (slack 확인)

  (5) 작업 끝: PUSH  (GitHub 에 올리기)
        Quartus : Tools > Tcl Scripts... > scripts/q_git_push.tcl > Run
        Questa  : source C:/Users/noelk/Vivado/scripts/q_git_push.tcl
      -> 마지막에 "GitHub PUSH done" 이 보이면 성공

  * 어느 툴에서 PUSH/PULL 해도 같은 저장소 전체가 올라가고 받아진다.
  * Vivado 프로젝트는 예전처럼 Vivado 툴바의 GitHub Push / Pull 버튼 사용.


[4] 새 작업(프로젝트) 만들기
---------------------------------------------------------------------
  1) projects/<새이름>/ 폴더와 project.tcl 만들기 (위 예시 복사, quartus_device 필수)
  2) PULL 한 번 실행 -> quartus/<새이름>.qpf 가 자동 생성됨
     (또는 명령 프롬프트:  quartus_sh -t scripts/quartus_proj.tcl projects/<새이름>)
  3) Quartus 에서 그 .qpf 열기


[5] 꼭 지킬 것
---------------------------------------------------------------------
  - 새 파일은 반드시 src/ sim/ sdc/ 에 만들기.
    Quartus 의 File > New 로 만들면 quartus/ 폴더에 저장되니, 저장 위치를 src/ 로 바꿀 것.
  - src/ sdc/ 에 파일을 추가/삭제하면 PUSH 나 PULL 할 때 .qsf 목록에 자동 반영됨.
  - 핀 배정(Pin Planner)은 .qsf 에 저장 -> PUSH 하면 다른 PC 로 감.
  - PC 를 바꾸기 전에 반드시 PUSH, 새 PC 에서 시작하면 먼저 PULL.
  - 두 PC 에서 같은 파일을 동시에 고치지 않기 (충돌 원인).
  - Questa 는 PC 한 대에서 창 하나만 (무료 라이선스 제한).


[6] 문제 해결
---------------------------------------------------------------------
  Q. Questa: "License checkout has been disallowed ... only one session is allowed"
     -> Questa 창이 이미 하나 열려 있음. 다른 창을 닫고 다시 실행.

  Q. Questa: 라이선스 에러 (license not found / expired)
     -> C:\altera_lite\license\license.dat 가 있는지 확인
     -> 환경 변수 SALT_LICENSE_SERVER / SALT_LICENSE_FILE 확인 후 Questa 재시작
     -> 2027-11-22 이후라면 SSLC 에서 같은 방법으로 재발급

  Q. Questa: "set sim_top in project.tcl (sim/ has modules: ...)"
     -> sim/ 에 모듈이 여러 개. project.tcl 의 sim_top 에 테스트벤치 이름 적기.

  Q. Questa: "Variable ... is multiply driven"
     -> 같은 신호를 두 군데서 구동하고 있음 (예: 출력 포트에 연결된 신호를 initial 로도 대입).

  Q. PUSH: "conflict with remote changes - aborted"
     -> 다른 PC 에서 같은 파일을 고쳐서 올렸음. 내 커밋은 이 PC 에 남아 있음.
        Claude 에게 "git 충돌 해결 도와줘" 라고 하기.

  Q. PUSH/PULL: "a previous merge/conflict is unresolved"
     -> 이전 충돌이 안 끝남. 터미널에서 git status 확인 (Claude 에게 부탁).

  Q. PULL 했는데 Quartus 화면에 새 파일이 안 보임
     -> Quartus 에서 q_git_pull.tcl 을 실행했는지 확인 (터미널 git pull 은 프로젝트를 다시 안 엶).
        Quartus 를 껐다가 .qpf 를 다시 열어도 됨.

  Q. 파일이 GitHub 에 안 올라감
     -> quartus/ 나 questa_work/ 안에 만든 건 아닌지 확인. src/ sim/ sdc/ 로 옮기기.
